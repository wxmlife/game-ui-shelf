# 图片自动整理与管理规格

## 目标

让用户把以游戏名称为一级文件夹的 UI 图片一次上传后，网站能按文件名自动生成正确的模块、图片标题、动作流顺序和可编辑标签；在游戏详情页可安全删除单图、批量图片或整本游戏，并可调整图片所属模块与模块内顺序。

## 导入命名

- 一级文件夹名称是游戏名称。
- 推荐文件名为 `模块_图片内容名称[_序号].扩展名`。
- `公会_兑换商店界面_2.jpg` 解析为：模块 `公会`、标题 `兑换商店界面`、动作流 `兑换商店界面`、顺序 `2`。
- 只把最后一个纯数字下划线段识别为顺序；标题内部其他下划线保留为内容分隔。
- 没有序号时按选择顺序从 1 开始。
- 保持兼容旧格式 `reward奖励-奖励详情.png`、`02-reward奖励-奖励领取.jpeg`。
- 原始文件名必须原样保存，Storage 对象路径继续使用 ASCII 安全键。

## 自动标签

- 上传预览时自动生成标签，仍允许人工编辑。
- 先加入模块词，再从标题中使用内置 UI 关键词词典和 `Intl.Segmenter` 提取关键词。
- 去重、过滤 `界面`、`页面`、`图片`、`截图`、`UI` 等泛词，最多 6 个标签。
- `公会_兑换商店界面_2.jpg` 至少得到 `公会`、`兑换`、`商店`。
- 搜索继续覆盖游戏名、模块、标题和标签。

## 图片移动

- 桌面端图片卡片提供显式拖拽手柄；拖到卡片左/右半边精确插入其前/后，拖到模块空白处或模块目录则追加到末尾。
- 移动端和键盘用户可点击“移动”打开对话框，同时选择目标模块和目标位置。
- 移动只改变模块、目标动作流和显示顺序；标题、标签、原始文件名、平台、版本及 Storage 文件均不变。
- 在目标模块中复用或创建同名动作流；动作流只作为图片资料，不再拆分显示网格。
- 同模块重排与跨模块移动都由服务端原子处理，并把受影响模块规范为 `1..N` 连续顺序；源模块变空后仍保留。
- 查看器的前后图片按整个大模块的统一展示顺序浏览。
- 图片标题、流程和标签等元数据的编辑接口不接受顺序值，保存元数据不得覆盖已经完成的排序。

## 平铺浏览

- 每个大模块只显示一个图片网格，按模块内展示顺序从左到右排满后换行。
- 动作流保留为可搜索、可编辑的图片元数据，但不再拆成只有一张图的小模块或独立网格。

## 删除

- 支持单图删除与跨模块多选批量删除。
- 删除前显示即将删除的图片数量并二次确认。
- 支持删除整本游戏；弹窗二次确认后直接执行，不要求重复输入游戏名称。
- 删除是永久硬删除；数据库元数据先在事务中删除，同时把原图、缩略图和封面路径写入持久化清理队列。
- 浏览器随后清理私有 Storage；失败项保留在队列，下一次加载或删除操作自动重试。
- 删除图片不删除自定义标签；删除或移动最后一张图后保留空模块。

## 游戏封面

- 游戏详情页的封面区直接提供“设置游戏封面”或“更换或调整游戏封面”入口。
- 封面从当前游戏的已有截图中选择，保存时复制为独立缩略图对象，不与原截图生命周期绑定。
- 保存横向/纵向焦点（`0..100`），书架横版与详情竖版都使用 `object-fit: cover` 并围绕同一焦点自动裁切。
- 编辑器同时预览两种比例，支持指针拖动和键盘可达的 X/Y 滑杆。
- 更换封面截图与保存焦点必须由同一 RPC 在一个数据库事务中完成；任一步失败都不能留下新封面配旧焦点的中间状态。只调整当前封面焦点时可使用独立焦点更新 RPC。

## 数据库迁移

- `202610160007_image_placement_and_cover_focus.sql` 增加模块内/跨模块精确排序、封面 X/Y 焦点、换封面与焦点原子保存，以及不写入顺序的元数据编辑接口。
- 已有 Supabase 项目按文件名顺序只执行尚未应用的 migration；不要重复执行已经上线的 migration。

## 验收

- 重新上传截图中的 `公会_*.jpg` 文件后只生成一个 `公会` 模块，标题与序号正确且自动标签可编辑。
- 可删除单张图片、一次删除多张图片、删除整本游戏。
- 可拖拽或通过对话框完成同模块重排与跨模块精确插入，除模块/流程/顺序外的资料不变。
- 每个大模块中的图片按统一顺序平铺，标题、流程或标签编辑后顺序保持不变。
- 更换封面和焦点原子保存，书架横版与详情竖版都围绕保存的同一焦点裁切。
- 删除或 Storage 清理部分失败时不产生孤立的数据库记录，后续加载可继续清理。
- 现有旧命名文件、搜索、图片编辑、上传和只读演示模式不回归。

## 手动一键更新

- 仓库根目录提供 macOS 可双击、也可在终端运行的 `update-site.command`。
- 每次运行提示输入本次更新内容；直接回车时精确使用默认提交信息 `feat:update`。
- 依次执行远端同步安全检查、完整测试、生产构建、暂存、提交和推送到 `origin/main`，由现有 GitHub Actions 自动部署 GitHub Pages。
- 支持把自定义提交信息作为命令行参数传入，避免交互输入。
- 若远端 `main` 不是当前提交的祖先，必须停止并提示先同步，不能强制覆盖远端。
- 没有文件变化时跳过提交，但仍可把已存在且已验证的本地提交推送部署。
- 任一步失败立即停止，不能在测试或构建失败后继续推送。
