# Game UI Shelf 设计规格

## 目标

构建一个部署在 GitHub Pages、供单个用户私有使用的游戏 UI 图片资料库。核心体验是像逛书架一样浏览游戏，进入游戏后按模块和动作序列查看 UI 截图，并能快速通过游戏名、模块、图片标题、标签、平台和版本找到素材。

## 成功标准

- 首页能以游戏封面卡片浏览资料库，并在一次搜索中找到游戏或截图。
- 游戏详情按模块分区，动作反馈相关图片按稳定顺序连续展示。
- 桌面浏览器可选择整个游戏文件夹，自动解析文件名并在上传前预览、纠正和排序。
- 原图保持原质量，列表使用 WebP 缩略图；点击后查看原图。
- 站点没有公开注册、投稿、审核、评论、点赞或社交系统。
- 未配置云端时提供可浏览的演示库；配置 Supabase 后启用单用户登录、私有图片和持久化上传。

## 信息架构

### 游戏书架

顶部提供全局搜索、上传入口和视图切换。主区域显示游戏卡片，卡片包含封面、名称、平台、截图数量和最近更新时间。侧边筛选器只保留平台、版本、模块和标签，默认折叠低频项。

### 游戏详情

详情页由游戏摘要、采集批次、模块导航和截图内容组成。页面按模块分组；模块内按动作流分组；动作流内的图片根据 `sequenceOrder` 排序。点击任意图片打开沉浸式查看器，并可前后浏览同一动作流、查看元数据和标签。

### 上传工作台

用户选择文件夹或拖入多张图片。导入器按以下规则建立草稿：

- 第一层文件夹名是游戏名，例如 `IDOL`。
- 文件名第一个连字符前是模块段，例如 `reward奖励`。
- 模块段中的连续拉丁字符形成稳定键 `reward`，其余文字形成显示名 `奖励`。
- 后续连字符段形成图片标题或动作步骤，例如 `奖励详情`、`奖励领取`。
- 可选数字前缀（如 `01-`）形成初始序号；没有序号时保持浏览器接收顺序并要求在预览中确认。
- 原始文件名始终保留。用户可在上传前修改游戏、模块、标题、标签和顺序。

## 数据模型

- `games`：游戏名称、别名、封面、开发商和更新时间。
- `capture_sets`：游戏下的平台、地区、版本、采集日期和来源备注。
- `modules`：游戏内模块键、名称和排序。
- `flows`：模块内动作流名称和排序。
- `ui_images`：原图与缩略图路径、标题、原始文件名、尺寸、顺序及搜索文本。
- `tags` 与 `image_tags`：用户自定义标签及图片关联。

所有业务表都带 `owner_id`，行级安全策略只允许当前登录用户访问自己的数据。Storage 使用私有 bucket，路径以用户 ID 开头；浏览器仅使用公开客户端密钥，绝不使用 `service_role`。

## 技术架构

- React、TypeScript、Vite 和 Hash Router 构建静态前端。
- GitHub Actions 构建 `dist` 并发布到 GitHub Pages。
- Supabase Auth 提供单个预建账户登录；关闭公开注册。
- Supabase Postgres 保存元数据并执行服务端筛选。
- Supabase Storage 私有保存原图与缩略图，通过短时 signed URL 展示。
- 浏览器在上传前生成最大边 560px 的 WebP 缩略图，并以小并发上传；大于 6MB 的原图走可续传上传的扩展接口，首版界面先明确显示建议。
- 未提供 Supabase 环境变量时使用只读演示仓库，便于本地预览和 UI 验证。

## 搜索

首版搜索游戏名、别名、模块、标题、标签、平台和版本。输入被去除首尾空白并转为小写；多个词采用全部命中语义。搜索结果分为“游戏”和“截图”，并支持标签、模块、平台和版本组合过滤。OCR、色值和视觉相似搜索不在首版，但数据库保留可选字段。

## 视觉方向

参考 Game UI Database 的“分类入口 + 游戏卡片 + 模块分组截图”结构，但减少资讯和导航层级。整体采用深墨色背景、暖白内容面、柠檬黄绿色强调色；大图优先、装饰克制、信息密度适合桌面设计工作。移动端保留浏览和搜索，文件夹批量导入以桌面端为主。

## 错误与恢复

- 文件格式、重复文件、缺少游戏名或上传失败在提交前逐项显示。
- 已成功上传的文件不会因同批次其他文件失败而重复上传，可重试失败项。
- 删除元数据前先删除对应 Storage 对象；失败时保留记录并提示重试，避免孤儿引用。
- 提供 JSON 元数据导出；原图仍可按游戏和批次从 Storage 下载。

## 非目标

公开社区、多人协作、审核队列、评论点赞、资讯视频、OCR、主色检索、视觉相似搜索、移动端批量文件夹导入，以及游戏百科资料均不属于首版。

## 验收

- `home首页.png`、`reward奖励-奖励详情.png`、`02-reward奖励-奖励领取.png` 能被解析为预期模块、标题和顺序。
- 搜索 `reward 奖励`、自定义标签或游戏名能返回正确截图；不匹配的多词查询为空。
- 私有模式下未登录用户看不到资料内容，登录用户只能访问自己的表记录和 Storage 对象。
- 书架、搜索、详情、查看器和上传预览在常见桌面宽度下可完整操作。
- 测试、类型检查和生产构建全部通过。
